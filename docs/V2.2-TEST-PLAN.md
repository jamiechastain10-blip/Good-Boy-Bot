# 2.2 test plan: the update system under a big change

2.2 is the first build meant to be pushed through the update system on purpose. It changes a lot at once:
- two new modules with new database tables
- a new core file (`src/modalpipe.js`) and a new key stored in the database
- `/warn` and `/announce` lose their options, so Discord has to re-sync commands
- every new button has to survive restarts

It adds **no new npm packages**, so the updater is allowed to apply it. (A release that needs `npm install` is downloaded but never applied.)

Work through the parts in order. Each check says what you should see. If something differs, note the step and the bot log line.

## Part A: before the update (on 2.1.2)

1. Run 2.1.2 through the supervisor: `npm run supervised`.
2. Note the current state: `npm run update -- status` should show `2.1.2`.
3. Back up `data/` yourself as well (the updater also does this, but this test is about trusting it).
4. In Discord, leave something open that 2.2 must cope with:
   - start `/announce send` with no options so its 2.1 popup is open, but **don't submit it yet**
   - have a few scheduled announcements (`/announce schedule`), including one with role pings

## Part B: publish 2.2.0

On the computer you publish from (see `docs/UPDATES.md` for the one-time key setup):

```bash
npm test
```

```bash
npm run release -- --key <folder>/release-private.pem --channel beta --notes-file CHANGELOG.md
```

Upload `dist/good-boy-2.2.0.tar.gz` and `dist/latest.json` to your update host. Use the **beta** channel for this test so stable installs are not offered it yet.

## Part C: install it

1. On the bot's computer set `UPDATE_CHANNEL=beta` in `.env`, restart the supervisor, then:
   ```bash
   npm run update -- check
   ```
   It should offer `2.2.0`. (Or use the dashboard's Updates page.)
2. Install it:
   ```bash
   npm run update -- install
   ```
   Expected: download → size, sha256 and signature checked → data backed up → bot stopped → switched → started → **reports ready within 2 minutes** → trial passes.
3. `npm run update -- status` should show `2.2.0`.
4. The bot log should show the migrations for `economy` and `games` running once, and commands re-syncing.

## Part F: rollback

1. Roll back:
   ```bash
   npm run update -- rollback
   ```
   2.1.2 should start again.
2. Check that 2.1.2 still works with the database 2.2 touched. 2.2 only **added** tables (`economy_*`, `games_*`) and a key in `schema_meta`; it changed no existing table. 2.1.2 ignores them because the modules don't exist in that version.
3. `/warn` and `/announce` show their old options again after Discord re-syncs. The 2.2 buttons now say "That control is no longer active".
4. Install 2.2.0 again. Wallets, fish and streaks are still there, because the data was never deleted.
5. **Automatic rollback (optional):** publish a throwaway `2.2.1-rc.1` to the `development` channel with `process.exit(1)` at the top of `src/index.js`. Installing it must fail the trial and roll back to 2.2.0 on its own, and the updater should remember 2.2.1-rc.1 as bad.
